# Run doc — Zenowing chat

## How to reproduce the artifacts

1. **Env file:** `.env` is already present in this workspace (gitignored, never
   commit). Current engine: **Ollama local** — `AI_BASE_URL=http://localhost:11434/v1/chat/completions`,
   `AI_MODEL=gemma3:4b`. The OpenAI block is kept commented for switch-back
   (needs an account with credit balance). `TTS_VOICE=pt-PT-DuarteNeural` (default).
2. **Ollama:** installed at 0.33.1+. Model pulled once:
   `ollama pull gemma3:4b` (3.3 GB). Also available locally: `mistral:latest`,
   `llama3.2:latest`. The Ollama service must be running (the Windows tray app
   or any `ollama` CLI call starts it).
3. **Python packages:** the server core needs nothing; the voice feature needs
   `edge-tts` installed in the interpreter that runs the server:
   `py -3.11 -m pip install edge-tts` (already done). Without it, TTS falls
   back to Windows SAPI voices automatically.
4. **Dependencies of the server itself:** none — standard library only.

## How to run the server

- **Command:** `py -3.11 -u server.py` from the project root
  (`C:\Users\RODRIGO\OneDrive\zenowing`). Run under Python 3.11 so `edge_tts`
  imports; under other interpreters the chat still works but the voice falls
  back to SAPI. `-u` only makes startup logs unbuffered.
- **URL/port:** http://127.0.0.1:3000/ — default port 3000. The server reads
  `PORT` from `.env`/environment but ignores invalid values (the shell exports
  a stray `PORT=0`, which previously made it bind a random port — guarded now).
- **Startup check:** stdout prints `Zenowing aguarda em http://localhost:3000`,
  then the engine URL and model.
- **Endpoints:** `GET /` (+ `/style.css`, `/app.js`, `/manifest.webmanifest`,
  `/sw.js`, `/icon-192.png`, `/icon-512.png`), `POST /api/chat`
  (streams plain text), `POST /api/tts` ({text} → mp3/wav audio).
- **PWA:** installable app. Icons are generated by `python make_icons.py`
  (pure stdlib, writes `public/icon-192.png` + `public/icon-512.png` — already
  generated). If static files change and the browser serves stale ones, bump
  `CACHE_VERSION` in `public/sw.js`.
- **Persona:** lives in `zenowing.md`; edits require a server restart to apply.
- **Known pitfalls (already solved, do not "fix" again):**
  - Original `HTTPServer.server_bind` reverse-DNS hang — bypassed in
    `server.py` (`ZenowingServer` subclass).
  - Invalid `PORT=0` from the shell environment — guarded in `resolve_port()`.
  - Models sometimes recite persona rules instead of enacting them — hardened
    with behavioral instructions + few-shot examples in `zenowing.md`.
  - msys64 python has no pip — install extra packages into the Windows Python
    3.11 (`py -3.11 -m pip ...`) and run the server with `py -3.11`.
- **Switching engine:** edit `.env` (`AI_BASE_URL`/`AI_MODEL`, uncomment the
  OpenAI block if needed) and restart the server.
